## 1. 项目背景与目标

### 1.1 背景
Chrome 浏览器默认书签管理存在明显不足：
- **无法搜索**：书签栏仅支持逐层点开，无全局搜索功能。
- **展示层级过浅**：书签栏仅展示一层（顶层文件夹），当用户收藏数量极大（如 5000+ 条、一级分类 10+ 个）时，无法快速浏览和定位。
- **空间利用差**：默认书签栏为水平单行，文件夹展开为下拉菜单，视觉承载信息量小，操作效率低。

### 1.2 目标
开发一款 Chrome 插件，**与原生书签栏共存**，提供独立的管理面板来增强书签体验，实现：
- 快速、多维度搜索书签。
- 清晰的**多级树状结构展示**，适应海量收藏。
- 提供多种颜色主题，满足个性化视觉需求。
- 维护工具：一键删除所有书签项中存储的 Base64 图标数据，以**减小收藏夹体积**。

---

## 2. 用户与使用场景

- **用户画像**：重度浏览器使用者，依赖书签管理庞大知识库/资源库（收藏数量数千级）。
- **典型场景**：
  1. 需要快速按关键词找到某个收藏已久的技术文章，但忘了放在哪个文件夹。
  2. 希望在一个面板中看到按分类树清晰排列的所有书签，直接点击进入。
  3. 收藏夹体积过大（大量 Base64 图标的 favicon 占用存储），需要一键清除这些冗余的图标数据，减小同步/本地数据库体积。

---

## 3. 核心功能需求

### 3.1 书签展示与导航

#### 3.1.1 多级树状结构
- 默认以**树形列表**展示全部书签和文件夹，支持无限层级展开/折叠。
- 节点信息：
  - 文件夹：名称、包含书签数量。
  - 书签：网站图标（favicon）、标题、URL（可部分显示或 hover 显示）。
- 树形交互：
  - 单击文件夹展开/折叠其子节点。
  - 单击书签在新标签页或当前标签页打开（可在设置中配置行为）。
  - 右键菜单支持：编辑、删除、在新窗口/隐身窗口打开等。

#### 3.1.2 作为独立弹窗（Popup）运行
- 插件通过工具栏图标打开一个独立弹窗，内部展示完整书签树。
- 弹窗尺寸建议宽 ≥400px，高 ≥500px，在技术可行下支持自由调整大小。
- 该弹窗与 Chrome 原生书签栏共存，不干扰原生书签栏的显示和使用。

#### 3.1.3 多选与批量操作
- 支持 Ctrl/Shift + 点击多选书签/文件夹。
- 批量操作：删除、移动到指定文件夹等。
- 拖拽移动：允许将书签或文件夹拖拽到其他文件夹内，实时同步 Chrome 书签存储。

#### 3.1.4 排序与视图
- 提供多种排序方式：按名称、创建时间、访问次数（Chrome 自带数据）、手动排序。
- 提供紧凑视图和正常视图切换（控制行高、图标大小）。

---

### 3.2 全局搜索功能

- 在插件界面顶部提供**实时搜索输入框**。
- 搜索范围：**所有书签的标题、URL**，可选择是否包含文件夹名称。
- 搜索结果呈现：
  - 平铺列表，高亮匹配关键词。
  - 显示每个结果的完整路径（所在文件夹层级，如“工作 > 前端 > React 文档”）。
  - 支持直接点击打开结果，或点击路径跳转到书签树中对应位置。
- 键盘快捷键：插件打开时，按 `Ctrl+F`（Mac `Cmd+F`）快速聚焦搜索框。

---

### 3.3 多套颜色主题切换

- 内置至少3套完整主题：
  - 浅色模式（明亮背景）
  - 深色模式（暗背景，护眼）
  - 高对比度主题或其他预设配色
- 主题切换入口：插件工具栏或设置面板中的下拉选择/按钮循环切换。
- 切换实时生效，不需刷新页面。
- 主题需覆盖所有界面元素：背景、文字、边框、选中高亮、滚动条、搜索框、按钮等。
- （进阶可选）允许用户从 5-8 种主题色方案中选择，或自定义主要背景和强调色，存入 storage。

---

### 3.4 图标清理工具：删除所有 URL 中存储的 Base64 图标

- **功能目的**：许多书签的 favicon 以 `data:image/...;base64,...` 形式直接保存在书签的图标字段中。这些 Base64 图标数据会显著增加收藏夹整体存储体积（影响本地数据文件大小及同步效率）。本功能用于一键清除这些冗余的 Base64 图标数据，释放空间。
- **具体描述**：
  - 提供一个功能按钮，命名为“清除 Base64 图标数据”或类似名称，放置在插件弹窗的设置区域或底部工具栏。
  - 执行逻辑：
    1. 遍历所有书签节点，检查每个书签的 favicon URL（或 Chrome 书签 API 中对应的图标相关属性）。
    2. 识别出图标 URL 以 `data:` 开头的书签。
    3. 将这些书签的图标字段重置为默认或空，让 Chrome 后续自动尝试从网站重新获取标准 favicon（`.ico`/`.png` 等）。
  - **绝不删除书签本身**，只清除内嵌的 Base64 图标数据。
- **用户体验**：
  - 执行前弹出确认框，列出将要清除的 Base64 图标书签的数量。
  - 可选择显示受影响书签的详细列表（名称+URL），并可勾选部分进行清除。
  - 清除后进行简要结果提示（成功清除了多少个图标）。
- **按钮位置**：建议放在设置面板或弹窗底部，使用清理/扫帚类图标。

---

### 3.5 书签管理操作增强

插件内嵌完整的增/删/改/移动功能，与 Chrome 原生书签同步：
- 添加书签：手动输入标题、URL、选择父文件夹。
- 添加文件夹：快速新建多级文件夹。
- 编辑：修改标题、URL。
- 删除：单条、多条或整个文件夹（需二次确认）。
- 书签有效性检查（可选，后期迭代）：一键检测死链，标记不可达书签。

## 4. 非功能需求

### 4.1 性能
- 5000+ 书签加载时间不应超过 2 秒（首次）。
- 树节点使用虚拟滚动或懒加载，只渲染可视区域，避免卡顿。
- 搜索响应速度：输入后 <200ms 展现结果。

### 4.2 兼容性
- 必须兼容 Chrome Manifest V3。
- 支持 Windows、macOS、Linux 上的 Chrome/Edge 桌面版浏览器。
- **仅考虑桌面端**，不考虑移动端。
- 弹窗在最小 400x500 分辨率下可用。

### 4.3 安全性
- 所有数据存储在用户本地，使用 Chrome Storage API，不上传书签到外部服务器。
- 遵循最小权限原则，申请 `bookmarks`、`storage` 等必需权限。

### 4.4 用户体验
- 界面响应流畅，提供展开/折叠动画。
- 图标显示应有懒加载和错误处理占位图。
- 提供键盘导航支持（方向键移动焦点，Enter 打开，空格多选等）。
- 预留国际化方案（先行支持中文）。

## 5. 界面与交互概要

**插件弹窗布局**：
1. **顶部工具栏**：左侧插件名称，中间搜索框，右侧主题切换按钮、设置按钮、清理图标按钮。
2. **主体区域**：书签树形列表，折叠箭头，缩进层级，鼠标交互反馈。
3. **底部状态栏**：显示总书签数、选中数，快捷新增按钮。

**设置页面**（通过齿轮进入，可作为弹窗内嵌标签或独立选项页）：
- 默认打开书签方式（新标签/当前标签）。
- 树状视图默认展开层级、紧凑度。
- 主题选择列表。
- “清除 Base64 图标数据”入口及说明文字。

## 6. 数据流与接口

- 使用 `chrome.bookmarks` API 获取书签树，并监听变化事件实时更新界面。
- 使用 `chrome.storage.sync` 或 `local` 存储用户配置。
- 对 favicon 展示：
  - 如果书签图标 URL 为常规 HTTP(S) 链接或标准 favicon 路径，正常加载。
  - 如果是 Base64 数据，也直接显示（图标清理前）。
  - 加载失败时显示默认占位图。
- 图标清理功能：
  - 通过 `chrome.bookmarks.getTree()` 获取所有节点。
  - 借助书签节点的 `url` 属性访问页面，但图标字段并非书签 API 直接暴露的 favicon URL。Chrome 会将 favicon 存储在内部数据库中，部分 Base64 图标可能作为缓存的“自定义图标”存在。开发时需研究具体实现方案（如使用 `chrome.favicon` 接口或内部驱动），确保能够识别并清除内嵌的 Base64 数据，达成缩小体积的目的。此项需技术预研并在设计阶段确定最终实现路径。

## 7. 技术方案建议

- 框架：React 或 Vue 3 构建弹窗 UI，便于维护和实现虚拟滚动。
- 虚拟滚动：react-window 或 vue-virtual-scroller。
- 打包工具：Vite/Webpack 输出 Manifest V3 扩展结构。
- 主题：CSS Variables 结合动态类名实现。

## 9. 明确事项与决策记录

- **共存策略**：插件作为独立弹窗运行，不修改或隐藏 Chrome 原生书签栏。
- **平台范围**：仅桌面端 Chrome/Edge，不涉及移动端适配。
- **图标清理定位**：清除的是书签自身的 Base64 favicon 数据，目的是减小收藏夹数据库/同步文件的体积，不涉及网页内图片或其他资源。
